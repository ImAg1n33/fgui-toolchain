## 1. P0 交付了什么

一条**纯离线**的确定性流水线，不依赖 FairyGUI / Unity / C# 环境：

```
切图目录 ──► R1 素材索引器 ──► assets.db + map.json + contact_sheet.html
                            │
PSD ×N ────► R2 PSD 解析器 ──► design_ir.{A,B}.json + ir_overlay.{A,B}.html
                            │
        R3 差异分析器 ────► change_plan.json ★人可读可改 + change_plan.md
```

| 命令 | 作用 |
|---|---|
| `asset-index` | 递归扫描切图，抽特征 + 九宫格三档判定 |
| `asset-search` | 三通道检索 + 人工确认写缓存（二次运行零重算） |
| `psd-ir` | 解析 PSD → Design IR（支持多份一次解析） |
| `diff-plan` | 两份 IR 的四级匹配 + 七类差异分类 |
| `selftest` | 一键跑通全链路 |
| `gen-xml` | **P1 桩**（见 §7） |

**三条红线**（都有自动化测试守护）：

| 红线 | 保障方式 |
|---|---|
| **禁网**（PRD K1） | 扫描 `src/` 零网络 API；11 个出站模块判 error；守卫自身经反向验证 |
| **确定性**（PRD B9） | 同一输入连跑 3 次，8 个产物 md5 逐字节一致 |
| **人可读**（PRD A10） | 每个产物带 `_comment` + 逐字段 `_fieldNote`；每条 diff 带 `evidence` |

### 2.1 九宫格判据的已知误判（6 项）

**当前实现**：新增 3 个特征（`midMonotonic` 一阶差分同号率 / `radialMaxCluster` 偏离扇区连续簇 /
`minSideForShape` 极小图保护）修掉了渐变面板、描边面板、浮雕按钮、极小图四类。

**仍未修的 6 项**（固化在 `test/unit/grid9-known-limits.test.js`）：

| 形态 | 当前判定 | 误判方向 | 严重度 |
|---|---|---|---|
| 细长横条纹 120×40 | `CAN_9GRID` | **危险侧**（该禁切却给建议可切） | 中（有兜底） |
| 细长竖条纹 40×120 | `CAN_9GRID` | **危险侧** | 中（有兜底） |
| 细长椭圆 160×80 | `SINGLE_AXIS_ONLY` | 安全侧 | 低 |
| **2px 细描边** 140×90 | `NEVER` | 安全侧 | 低 |
| 内阴影+渐变 3px 描边 160×70 | `NEVER` | 安全侧 | 低 |
| 极小图 10×10 纯色 | `CAN_9GRID` | 危险侧 | 低（已提阈值至 12，本轮修） |

**为什么「危险侧」但仍可接受**（QA 第二轮独立复核认可）：
1. 严重度低于 BUG#1/#2 那两个 P0（那两个会让人工校验手段本身失效）；
2. **有兜底** —— `grid9` 只产出**建议**，不直接改 FGUI 工程；
   小 Q 在 `change_plan.md` 里看到 `CAN_9GRID` 后人工确认这一步能拦住。
3. 技术判断正确 —— 细长条纹与描边面板在 `cornerFill`（都=1.0）、
   `radialSymmetry`（都=1.0）、`radialMaxCluster`（都=2）上**完全相同**，
   唯一差别 `midMonotonic`（0.556 vs 0.5）差异量级不足以支撑稳健阈值。
   硬调阈值只会把「已知错」换成「另一种错」。

**P1 该怎么办**：
- 不要在合成数据上继续调阈值（那不是标定）；
- 拿到真实素材后跑一次回归，用 `fgui.config.json` 的外置阈值标定；
- 若要根治，需**新增两个特征**：簇的**角度位置**（描边=正交四向 / 条纹=平行两向）、
  中线的**周期性**（条纹周期重复 / 边框一次突变）。

### 2.2 ⚠️ 描边判据对 2px 细描边敏感（**按 QA 第二轮的结论更正描述**）

我在第一轮说「对描边宽度敏感」，QA 做了 9 档扫描后给出**更准确**的结论：

| 描边宽度 | 判定 |
|---|---|
| 1px | `CAN_9GRID` ✅ |
| **2px** | **`NEVER`** ⚠️ |
| 3px ~ 20px | `CAN_9GRID` ✅ |

**不是「越粗越 NEVER」，而是「2px 是孤立异常点」**（`radial` 恰好落在阈值附近）。
真实素材最常见的 1–4px 描边里只有 2px 落在风险窗口，**大面积出问题概率低**。
误判方向是安全侧（判 NEVER → 人工手切 10 秒）。

### 2.3 MAX_DEPTH 超限静默降级（**实际不可达**）

`deriveGroupBox` 有 256 层嵌套上限，超限降级为「跳过」。
真实 PSD 极少超过 10 层，**判定为实际不可达**。

但为防止将来真出现时无从排查，本轮已加信号：
返回值带 `depthTruncated` 计数，IR 的 `_derive.depthTruncated` 记录它，
告警文案会明说「因深度上限降级」而非「坐标异常」。

### 2.4 🔴 真实 PSD 可能没有切片 → **L1 通道作废（架构级，第一轮就列，至今未解决）**

**这是 P1 最需要知道的一条。**

- L1（slice 名一致）是**最强匹配通道**，预计覆盖 30–50%；
- 但它依赖 PSD 内保留导出切片信息；
- **画师导出后往往不保存切片** → 真实 PSD 很可能没有切片；
- 那样 L1 完全失效，只能退化为 L2（归一化名全等）+ L3（pHash）；
  **匹配准确率会显著下降**。

**P1 该怎么办**：
- 开工前先确认小 Q 的真实 PSD 有没有切片（见 §3 的 Q7）；
- 若无切片，**提前和画师约定导出时保留切片** —— 这是零成本的预防；
- `design_ir.json` 的 `sliceNames` 为空数组 + `warnings` 里有 `NO_SLICE` 时，
  工具已会明确告知「L1 不可用，将退化为 L2+pHash」。

### 2.5 其它必须知道的边界

| 项 | 说明 |
|---|---|
| 颜色**只用 6 位** | `#RRGGBBAA` 运行时只取后 6 位 → 纯蓝。透明度走 `alpha="0.x"` 属性 |
| 字段名拼写是 `extention` | 不是 `extension`。这是上游拼写，别「顺手修正」 |
| `ui://` 包 id 必须 8 位 | 非 8 位会吃掉 itemId 首字符 |
| **不使用** `OpenDocument` | 静默失败 / 被 unity 裁剪 |
| **不使用** `screenshot` | truthy 但不可调用；改 OS 级截屏 |
| 编辑器开着时**不手写** `package.xml` | 会被内存态覆盖 |
| 1x/2x 倍图**未处理** | Q22 未答；当前 ±2px 容差是按 1x 假设设计的 |
| 繁体映射表是**精简内置表** | 不是完整 OpenCC；词典可配置，缺失时降级且降级可见 |

## 5. P1 的实现路线（架构 §5.2 选 C）

```

② 生成候选 XML 到内存

⑤ 复检 tmp 内容                    ── 有 error ─→ 删 tmp，退出码 3
```

2. **加「测试自身有效性」的反向断言**（如「若递归与非递归结果相同，说明 fixture 仍掩盖 bug」）；
3. **让 QA 的独立脚本能跑**（`npm run qa`），不要只在自己的测试里绿。

### 9.2 静默错误比崩溃危险

P0 的两个 P0 静默错误（组 bbox 偏小、合成图全黑）**都不报错、页面能开、框能画**，
但都让**人工校验手段本身失效**。

P1 写 XML 生成时请守住同一条原则：

> **宁可明确报错，不要静默给错东西。**

已建立的范式（请沿用）：

| 场景 | 做法 |
|---|---|
| 合成图退化 | `validateComposite` 判 `degenerate` → **不放底图 + 红色警告** |
| 合成图信息量少 | 判 `lowInfo` → **照常显示 + 黄色提示**（不与真失败同级） |
| 组 bbox 推不出来 | `EMPTY_GROUP` / `GROUP_BBOX_UNRESOLVED` 告警，且**区分超深降级与坐标异常** |
| 匹配不确定 | `INFERRED` + `defaultIfUnconfirmed='skip'` |
| 守卫不确定 | `error`（确定有网络能力）vs `warn`（需人工看一眼）分级 |
